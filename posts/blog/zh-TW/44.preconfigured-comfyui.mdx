# 提供預先設定 ComfyUI 映像的 GPU 雲端：Glows.ai 工作流程指南

提供預先設定 ComfyUI 映像的 GPU 雲端，能為圖像生成提供實用的起點：你可以從現成的 ComfyUI 環境開始，專注於要執行的模型與工作流程。Glows.ai 提供多種 ComfyUI 映像，包括 ComfyUI FLUX.1-Kontext、ComfyUI Qwen Image、ComfyUI Wan2.2 14B I2V 與 ComfyUI LTX-2.3，以及 ComfyUI Base 等框架映像。

接下來要做的是將該映像轉化為可重現的工作環境。檢查環境、確認模型檔案與節點相符、確保存取安全、執行小型範例，並儲存還原所需資料。這套步驟能幫助你判斷，工作流程是否只是成功啟動，還是能夠放心地再次開啟使用。

## 從你打算完成的工作流程開始

選擇硬體前，先決定一項任務：編輯現有圖像、生成靜態圖像，或開發更複雜的節點圖。記錄模型系列、預計解析度、批次大小、所需的自訂節點，以及預期的輸出類型。為某個模型系列設計的工作流程，可能需要與其他系列不同的編碼器、載入器或適配器。

如果要做 FLUX.1-Kontext 專案，可以選擇 ComfyUI FLUX.1-Kontext 映像，內含 Ubuntu 24.04、CUDA 12.8、Python 3.11、PyTorch 2.7.1、ComfyUI、FLUX.1-Kontext 與 VNC。啟動前，請確認所選 GPU 與工作流程符合映像的需求。

如果你想自行組建環境，框架映像也很實用。啟動前請閱讀所選映像的說明；僅憑熟悉的 ComfyUI 名稱，無法判斷其中有哪些模型權重與自訂節點。

## 1. 確認映像、模型與 GPU 相互搭配

使用簡短的檢查清單，讓部署決策更具體：

| 項目 | 首次執行前應確認的事項 |
| --- | --- |
| 映像 | 確切的映像名稱與所列軟體版本 |
| 工作流程 | 模型系列、必要節點與預期輸入 |
| 權重 | 確切的checkpoint、編碼器、VAE 與適配器需求 |
| GPU | 可用的 VRAM，以及對所選軟體組合的支援 |
| 檔案 | 下載大小、工作空間與輸出儲存位置 |

GPU 記憶體需求會隨精度、解析度、批次大小及節點圖本身而變化。Glows.ai 上的 RTX 4090 配備 24GB VRAM，但這項規格並不保證每個 FLUX 或影片工作流程都能容納。請為中間張量及其他已載入元件預留空間，再測試實際的節點圖。如果記憶體不夠，Glows.ai 也有 48GB（RTX 6000 Ada、L40S）與 80GB（A100、H100）的 GPU 可以選。

第一次操作時，避免直接執行大批次。先跑一個小型且具代表性的工作流程，可以在投入更多計費時間之前，更清楚地了解缺少哪些檔案及記憶體壓力。

## 2. 建立受控的存取方式

Glows.ai 支援透過 SSH 操作實例。請使用所選部署提供的存取資訊，檢查檔案、閱讀日誌並管理環境。是否提供 VNC，取決於映像。

個人使用時，最簡單又安全的方式是透過 SSH 通道開啟 ComfyUI。ComfyUI 使用 8188 port，本身沒有登入機制，只要在實例 Access 頁的 SSH Command 加上 `-L 8188:localhost:8188`，保持連線，再用瀏覽器開啟 `http://localhost:8188` 即可。

不要將憑證與存取網址放入共用的工作流程檔案或公開截圖。如果其他人也要使用介面，請先設定身分驗證，並用 Glows.ai 的 IP ACL 只允許公司或 VPN 的 IP 連線，再上傳私人素材。只開放這次工作需要的連接埠。

當介面沒有回應時，先檢查服務是否正在執行，並查看日誌。反覆重新啟動實例可能掩蓋原始錯誤，增加設定時間，卻無法解決缺少相依套件的問題。

## 3. 有步驟地處理模型與自訂節點

載入與所選模型相符的工作流程。分別檢查缺少模型與缺少節點的訊息：安裝節點套件不會同時提供其checkpoint，而下載checkpoint也不會安裝用來載入它的程式碼。

針對每個必要的權重檔案，記錄來源、檔名、模型系列、精度，以及在所選映像中的儲存位置。請依照工作流程的說明與映像實際的目錄結構操作。從其他部署複製的路徑，可能在原處有效，卻不適用於目前的環境。

自訂節點會將可執行程式碼引入環境。安裝前，請檢查其原始碼與相依套件需求；在排查單一錯誤時，避免一次更新所有擴充套件。每次只變更一個元件，並記錄可正常運作的版本。取得權重時，請遵守模型的授權與存取條件。

當節點圖包含多個編碼器、LoRA、放大器或前處理階段時，這些準備尤其有幫助。每個元件都需要與流程中的其他部分相容。

## 4. 驗證一個小型範例

從一個輸入、一個輸出，以及適合模型的保守設定開始。如果工作流程支援，請固定隨機種子，以便比較後續變更。目標是驗證從輸入到儲存輸出的完整路徑。

確認預期的 checkpoint 已載入、節點圖已執行完成，且輸出符合要求的尺寸與格式。執行時可以在實例頁的 Monitor 查看 GPU 記憶體與使用率的變化，同時查看日誌。接著重複執行同一個範例。首次載入模型與後續生成是不同階段，請分別記錄。

如果記憶體不足，請在工作流程允許的情況下降低批次大小或解析度，檢查哪些元件仍留在記憶體中，並重新考慮精度或硬體選擇。較小的檔案可以減少權重占用的記憶體，但其他部分的記憶體需求仍可能很高。不要一次變更多項設定，以免無法判斷究竟是哪項調整解決了問題。

只有在這個範例成功執行後，才擴大批次。針對你實際計畫執行的工作負載，記錄總耗時與成功輸出數量，不要將第一次預覽當作效能基準測試。

## 5. 結束前儲存還原所需資料

匯出工作流程，並將輸入素材及選定的輸出儲存到由你掌控的位置。另附一份簡短清單，包含映像名稱、模型檔名、自訂節點版本、生成設定，以及重建工作環境所需檔案的位置。

Datadrive 可以在每次使用之間保存模型檔、輸入素材與輸出，下次不用重新下載大型權重，也可以不開實例就先上傳權重。裝好自訂節點後存一份 Snapshot，下次就能用同樣的環境開機。實例硬碟在釋放後會清除，記得先存好。匯出的工作流程通常只是描述節點圖，並不會將執行所需的所有權重檔案與相依套件一起打包。

實用的還原檢查方式，是重新開啟匯出的工作流程，依照儲存的清單再次執行小型範例。這樣能在原始環境仍可使用時，找出缺少的輸入或未記錄的相依項目。請勿將機密資訊放入還原資料中。

## 將整段使用時間納入成本

Glows.ai 的 GPU 運算按秒計費。規劃時可參考 2026 年 10 月 RTX 4090 每 GPU 小時 $0.49 的價格。假設使用一張 GPU，計費時間為 20 分鐘，運算費用約為 $0.16。這是實例費用的示例，並非端點價格，也不是實測的生成成本。

估算使用時間時，請納入初始化、模型下載、疑難排解與閒置時間。按秒計費只需支付實例運行的時間，釋放實例後就停止計費；節點圖跑完並不會停止計費。

## 同一套規劃能同時適用於 vLLM 與 ComfyUI 嗎？

Glows.ai 也列有 vLLM 映像，但這些工作負載應分別評估。ComfyUI 的驗證重點是節點圖、媒體輸出與模型元件；LLM 伺服器則需要檢查上下文長度、併發量與回應延遲。使用同一個雲端帳戶，不代表兩者的記憶體需求可以互相套用。

下一次使用 ComfyUI 時，先完成一個經過驗證的小型工作流程，並備妥還原所需資料。這能在你提高解析度、新增節點或分享操作方法時，為創作工作提供可靠的起點。
