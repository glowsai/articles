## 每 GPU 小時 $0.49 代表什麼？

每小時單價是描述運算成本的計價單位。按秒計費時，將適用的計費秒數換算成小時，再乘以單價。

運算費用 = 計費秒數 ÷ 3,600 × $0.49。

以 11 月參考價格使用一張 GPU：

| 假設計費時長 | 運算費用，四捨五入後 |
| --- | --- |
| 45 分鐘 | $0.37 |
| 2 小時 | $0.98 |
| 8 小時 | $3.92 |
| 20 小時 | $9.80 |

這些僅為運算費用示例，不是工作負載效能測試、保證的使用時長或完整帳單。請確認資源配置規模、目前配置與另外收費的服務。比較時，也要納入各供應商的四捨五入與最低收費規則。

標示每小時價格，不代表必須使用 GPU 整整一小時。同樣地，按秒計費也不代表設定、載入或資源已配置但閒置的時段免費。

## 哪些工作值得在 24GB GPU 上測試？

當完整執行方案能容納於 24GB VRAM 時，RTX 4090 值得評估。這不只包含模型權重。

| 工作負載 | 主要的記憶體適用性問題 |
| --- | --- |
| LLM 推論 | 權重、執行期緩衝區與預定的 KV 快取能否同時容納？ |
| LoRA 或 QLoRA 實驗 | 活化值、最佳化器狀態與所選序列／批次設定能否容納？ |

| ComfyUI | 能否容納節點圖、模型、自訂節點與輸出設定所需資源？ |

不要從顯示卡名稱推斷通用的模型參數量上限。量化、上下文長度、併發量與實作方式，都可能大幅改變實際記憶體占用。

如果工作負載需要更多記憶體，請比較較大記憶體的配置，而不是勉強採用妥協的執行方案。正確目標是以合適的成本取得合格結果，而非追求最低的每小時價格。

## 五個步驟建立試行

### 1. 定義結果

選擇一項具代表性的工作及其驗收條件：通過驗證的檢查點、完成的圖像節點圖，或一組有用的模型回應。固定模型版本、輸入、精度與相關品質要求。

### 2. 確認資源配置

確認方案為預期的 RTX 4090 配置，且每張 GPU 配備 24GB。確認 GPU 數量、CPU/RAM、儲存安排、當前價格與計費生命週期。多 GPU 或整個節點的方案，需要獨立確認總價。

### 3. 檢查環境

確認環境能辨識 GPU、所需軟體已安裝，且所有必要檔案均可使用。記錄相依套件版本與啟動指令。透過專案慣用且可信賴的流程，安裝或下載缺少的項目。

### 4. 測試實際輸入規模

使用所需的解析度、上下文長度、批次大小或請求重疊程度執行。簡短示範可能無法呈現實際工作負載稍後才出現的記憶體峰值。除了程序是否完成，也要檢查輸出品質。

### 5. 儲存、取回並釋放資源

保留程式碼版本、配置、輸出與必要的檢查點狀態。測試預定的取回流程、確認保留條款，並在結束時確認資源的計費狀態。關閉瀏覽器不代表運算計費已結束。

## 為整段使用時間編列預算

假設一次使用包含 20 分鐘準備、60 分鐘執行任務，以及資源已配置的 10 分鐘閒置時間。如果全部 90 分鐘均需計費，運算費用為 1.5 × $0.49 = $0.735，約為 $0.74。

只計算任務的 60 分鐘，會漏掉這次使用中三分之一的計費時長。也請納入重試與疑難排解，並將另外收費的服務加入總成本。

對於重複執行的工作，請分別記錄準備與執行時間。可重複使用的環境可能減少後續設定工作，但應確認所需檔案與設定能透過實際採用的儲存流程保留下來。

## 租用雲端 RTX 4090，還是組裝本機 GPU 電腦？

對於偶爾進行的專案、臨時容量需求，以及購買另一台機器後會有大量閒置容量的實驗，雲端租用具有吸引力。如果需要長期持續使用、有本機資料需求，或已擁有系統，本機電腦可能更合理。

比較完整本機系統成本、電費、維護與預期的有效工作時數，再對照雲端的總費用、資料搬移與操作投入。顯示卡購買價格，不等於整台可運作工作站的成本。

將硬體預算除以 $0.49，只能得到簡化的運算時數比較。如果沒有納入其他成本與實際工作負載的效能，就無法據此確定真正的損益平衡點。

## 常見租用問題

### 租用的 RTX 4090 可以執行任何 LLM 嗎？

不行。完整推論或訓練方案必須符合硬體與軟體環境。請驗證確切的模型、精度、上下文與併發量。

不會。軟體必須明確分散工作或模型。RTX 4090 不支援 NVLink，多張卡也不會自動提供單一共用記憶體空間。任何提議的多 GPU 配置，都應另外確認。

### 使用結束後應檢查什麼？

確認產出檔案的取回、保留與資源計費狀態。工作完成、模型卸載與資源釋放，是不同的事件。
