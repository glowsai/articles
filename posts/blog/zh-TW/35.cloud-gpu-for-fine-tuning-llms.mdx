# 如何選擇適合 LLM 微調的雲端 GPU：開發者指南

選擇適合 LLM 微調的雲端 GPU 時，應比較記憶體是否足夠、軟體相容性，以及完成一次訓練的成本。配備 24 GB VRAM 的 NVIDIA RTX 4090，可作為較小規模 LoRA 或 QLoRA 實驗的實用起點。較大的模型、較長的上下文或全參數訓練，可能需要更多記憶體或多張 GPU。在投入長時間訓練前，先透過短程試跑驗證配置。

Glows.ai 適合希望使用按秒計費的隨需 GPU、自行設定訓練流程的開發者。公開價格中，RTX 4090 每 GPU 小時自 $0.49 起；A100 80GB 與 H100 80GB 則分別為每 GPU 小時 $1.20 與 $2.59。Glows.ai 提供 GPU 基礎設施與訓練環境，而非一鍵微調服務。

## 1. 依微調方法選擇 GPU

載入模型所需的記憶體，只是訓練需求的一部分。還必須為梯度、最佳化器狀態、啟用值及暫存緩衝區預留空間。模型大小、精度、序列長度、微批次大小與訓練方法，都會影響記憶體使用峰值。

- 全參數微調：更新所有模型參數。視模型與最佳化器而定，訓練狀態所需的記憶體可能遠高於單純儲存權重的需求。

- LoRA：凍結基礎模型，只訓練少量適配器參數。這能減少可訓練狀態，但基礎模型權重與啟用值仍會占用記憶體。

- QLoRA：結合量化基礎模型與可訓練適配器，以降低記憶體需求。模型、量化函式庫與訓練框架必須彼此相容。

| 配置 | 適合評估的情境 | 需要驗證的項目 |
| --- | --- | --- |
| RTX 4090 · 24 GB VRAM | 較小規模的 LoRA 或 QLoRA 試跑 | 在預定序列長度與微批次大小下的記憶體使用峰值 |
| A100 80GB 或 H100 80GB | 記憶體需求超過 24 GB GPU 容量的工作 | 達到相同品質目標時的記憶體餘裕、執行時間與成本 |
| 多張 GPU | 超過單張 GPU 記憶體容量，或需要更高吞吐量的工作 | 框架支援、互連方式與實際擴展效率 |

多張 GPU 不會自動形成單一共用的 VRAM 池。FSDP、ZeRO、張量平行或管線平行等技術，都需要適當的軟硬體支援。規劃分散式訓練前，先確認可用的 GPU 配置與節點拓撲。

## 3. 最佳化完成一次訓練的成本

最低的每小時價格，不一定帶來最低的訓練費用。速度較快的 GPU 可能更早完成相同工作；記憶體較少的 GPU 則可能需要採用較慢的配置，才能避免超出容量限制。

GPU 運算成本 = GPU 數量 × 每張 GPU 的每小時費率 × 計費執行時數

舉例來說，單張 RTX 4090 以每 GPU 小時 $0.49 執行 10 小時，GPU 運算成本為 $4.90。若相同工作負載在一張 A100 80GB 上，能於四小時內達到相同的驗證品質目標，以每 GPU 小時 $1.20 計算，運算成本為 $4.80。這些執行時間是示意假設，並非基準測試結果。

計算完整專案成本時，應納入適用的儲存、資料傳輸與其他服務費用，也要計入設定時間、閒置執行個體，以及訓練失敗後重試的成本。

調整訓練設定後，應重新量測記憶體用量與吞吐量。梯度檢查點技術以額外計算換取較低的啟用值記憶體需求，不一定能縮短訓練時間。儲存供復原使用的檢查點則是另一項操作，會增加儲存 I/O，但能減少失敗後損失的訓練進度。

## 4. 建立可重複執行的訓練流程

適合的環境與 GPU 同樣重要。Glows.ai 的映像目錄包含 PyTorch 環境與 LLaMA-Factory。開始前，請確認所選映像的配置與相容性；有可用映像，不代表每個模型或訓練方案都能不經調整直接執行。

1. 選擇環境。確認模型與微調框架，能配合映像中的 Python、CUDA、PyTorch 與量化函式庫版本。應選擇訓練環境，不要直接假設推論映像也適合微調。

2. 準備存取方式與資料。使用 SSH 或 JupyterLab 設定工作。上傳資料或下載權重前，先確認資料集權限、斷詞處理、訓練與驗證資料切分，以及模型授權要求。

3. 記錄配置。對程式碼、資料集、基礎模型、斷詞器、相依套件清單與超參數進行版本管理。記錄隨機種子及相關執行設定，讓實驗更容易重複與比較。

4. 規劃檢查點儲存。選擇訓練執行個體結束後仍可使用的儲存位置。確認保留、存取與復原方式，並在長時間訓練前測試檢查點的儲存與重新載入。

5. 協調團隊存取。共同作業時，Glows.ai Team 可將 GPU 資源、環境、資料集、權限與配額集中在同一個工作空間。平行執行多項實驗前，先約定命名方式、負責人與預算上限。

## 5. 以相同基準比較供應商

比較 Glows.ai、RunPod、Vast.ai、Lambda、GMI Cloud 或 AWS 時，應使用條件一致的工作負載評估，而非只看標示價格。GPU 市集與 Spot 執行個體並不是同一回事：市集可能提供不同類型的方案，而 Spot 或可中斷條款則說明運算資源是否可能被收回。

| 比較項目 | 採用前應確認的問題 |
| --- | --- |
| 硬體與訓練需求 | GPU 版本、VRAM、GPU 數量與互連條件是否可比？ |
| 價格與中斷政策 | 方案是隨需型還是可中斷型？哪些項目另行計費？ |
| 環境與流程 | 框架、相依套件與檢查點流程能否依需求運作？ |
| 資源供應與復原 | 所需配置是否可用？工作失敗時會如何處理？ |
| 實測成果 | 達到相同驗證目標的總成本是多少？ |

比較等效配置時，應採用標有日期的公開隨需價格。Spot 或可中斷方案應另外評估，並納入復原需求與可能的重試成本。

## 6. 擴大規模前先驗證配置

使用預定模型、序列長度與訓練方法，執行具代表性的試跑。短程訓練能找出記憶體與相容性問題，但不能取代最終模型的評估。

- 記憶體：記錄 VRAM 使用峰值，包括驗證與儲存檢查點的階段，並為工作負載變動預留空間。

- 吞吐量：量測有效的訓練吞吐量，確認資料載入或檢查點 I/O 是否限制 GPU 效能。

- 品質：追蹤能反映任務需求的驗證指標。在相同品質目標下比較配置，而不只是比較相同時間內的表現。

- 復原：測試檢查點儲存與重新載入。若需要接續訓練，除了模型權重，也應保留相關最佳化器、排程器及其他訓練狀態。

- 成本：根據實測效能估算完整訓練成本，並在較長的試跑後重新評估。納入評估、重試與閒置運算的成本。

### 另外確認資料處理要求

GPU 效能不能證明服務符合安全或法規要求。使用敏感資料前，應確認處理地點、存取控制、傳輸中與靜態資料加密、日誌處理、保留及刪除政策，以及必要的契約保障。不要假設全球分散式服務必然提供特定的資料落地保證。

### 規劃從訓練轉入推論的交接

匯出訓練後的權重或適配器時，應一併保留基礎模型與斷詞器的版本及配置。確認推論執行環境支援所用架構、量化方式與適配器格式；只有部署流程需要且支援時，才合併適配器。將正式流量導向模型前，先驗證輸出品質與負載下的表現。

Glows.ai 提供支援自動擴縮的 Inference on Cloud，以及提供隔離推論資源的 Inference on Dedicated Cloud。模型相容性與部署需求應另行確認，不能只依據訓練配置判斷。

## 常見問題

### Glows.ai 適合用於 LLM 微調嗎？

如果你需要隨需 GPU 基礎設施、按秒計費，以及自行掌控訓練環境，Glows.ai 是合適的選項。RTX 4090 24 GB 每 GPU 小時自 $0.49 起；需要更多記憶體的工作，也可考慮 A100 80GB 與 H100 80GB。你仍須自行選擇並設定模型、資料集與微調框架。

### 可以從 RTX 4090 開始微調嗎？

可以，配備 24 GB VRAM 的 RTX 4090 可適用於部分 LoRA 或 QLoRA 實驗。是否足夠取決於模型大小、量化方式、上下文長度與批次設定。應以預定配置測試記憶體需求，不要假設能載入的模型就一定能完成訓練。

### Glows.ai 提供一鍵 LLM 微調嗎？

Glows.ai 提供 GPU 基礎設施，以及 PyTorch、LLaMA-Factory 等環境，而非一鍵微調服務。使用者需要依所選流程設定訓練框架、相依套件、資料集與參數。

### GPU 每小時價格越低，就一定越便宜嗎？

不一定。應針對相同任務與品質目標，比較 GPU 數量、計費執行時間及其他適用費用。如果較高費率的 GPU 能大幅縮短完成時間，總成本仍可能更低。請使用實測訓練效能評估，不要假設固定的加速倍數。

### 如何讓不同執行個體上的實驗可重複執行？

對程式碼、資料、基礎模型、斷詞器、相依套件與訓練設定進行版本管理。將檢查點存放在確認可於執行個體生命週期結束後保留的儲存空間，並測試還原。僅儲存環境，無法涵蓋所有相依條件，也不能保證結果完全一致。

### 什麼時候應考慮使用多張 GPU？

當合適的單張 GPU 無法容納訓練工作，或實測顯示擴展能改善完成時間或成本時，可考慮多張 GPU。確認框架、互連與節點拓撲支援你的平行策略。增加 GPU 數量不保證能得到等比例的加速。
