# GPU Cloud with a Preconfigured ComfyUI Image: A Glows.ai Workflow Guide

A GPU cloud with a preconfigured ComfyUI image gives you a practical starting point for image generation: you can start with a ready-made ComfyUI environment and focus on the model and workflow you want to run. Glows.ai offers many ComfyUI images, including ComfyUI FLUX.1-Kontext, ComfyUI Qwen Image, ComfyUI Wan2.2 14B I2V, and ComfyUI LTX-2.3, alongside framework images such as ComfyUI Base.

The useful next step is to turn that image into a repeatable working session. Check the environment, match the model files and nodes, secure access, run a small sample, and save a recovery package. That sequence helps you distinguish a successful launch from a workflow you can confidently reopen.

## Start with the workflow you intend to finish

Choose one task before choosing hardware: edit an existing image, generate a still image, or develop a more elaborate graph. Record the model family, intended resolution, batch size, required custom nodes, and expected output type. A workflow designed for one model family may require different encoders, loaders, or adapters from another.

For a FLUX.1-Kontext project, the ComfyUI FLUX.1-Kontext image includes Ubuntu 24.04, CUDA 12.8, Python 3.11, PyTorch 2.7.1, ComfyUI, FLUX.1-Kontext, and VNC. Before launch, check that your chosen GPU and workflow meet the image’s requirements.

A framework image is also useful when you want to assemble the environment yourself. Read the selected image description before launch; a familiar ComfyUI name alone does not tell you which model weights and custom nodes are present.

## 1. Match the image, model, and GPU

Use a short checklist to make the deployment decision concrete:

| Component | What to establish before the first run |
| --- | --- |
| Image | Exact image name and listed software versions |
| Workflow | Model family, required nodes, and expected inputs |
| Weights | Exact checkpoint, encoder, VAE, and adapter requirements |
| GPU | Available VRAM and support for the selected software stack |
| Files | Download size, working space, and output destination |

GPU memory requirements change with precision, resolution, batch size, and the graph itself. An RTX 4090 has 24GB of VRAM on Glows.ai, but that specification is not a promise that every FLUX or video workflow will fit. Leave room for intermediate tensors and other loaded components, then test the actual graph. If your graph needs more memory, Glows.ai also offers 48GB GPUs (RTX 6000 Ada and L40S) and 80GB GPUs (A100 and H100).

Avoid making your first session a large batch. A small, representative workflow gives you a clearer view of missing files and memory pressure before you commit more billable time.

## 2. Establish controlled access

Glows.ai supports SSH for working with your instance. Use the access details provided for your selected deployment to inspect files, read logs, and manage the environment. VNC availability depends on the image.

The simplest private way to open the ComfyUI interface is an SSH tunnel. ComfyUI runs on port 8188 and has no built-in login, so add `-L 8188:localhost:8188` to the SSH Command from your instance's Access tab, keep the session open, and open `http://localhost:8188` in your browser.

Keep credentials and access URLs out of shared workflow files and public screenshots. If teammates need the interface too, set up authentication and use Glows.ai IP ACL to allow only your office or VPN addresses before uploading private assets. Open only the ports the session needs.

When the interface does not respond, first check whether the service is running and review its logs. Repeatedly relaunching the instance can hide the original error and add setup time without fixing a missing dependency.

## 3. Resolve models and custom nodes deliberately

Load a workflow that matches the selected model. Inspect missing-model and missing-node messages separately: installing a node package does not supply its checkpoint, and downloading a checkpoint does not install the code that loads it.

For each required weight file, record its source, filename, model family, precision, and destination in the selected image. Use the workflow's instructions and the image's actual directory layout. A path copied from another deployment may be valid there and wrong here.

Custom nodes introduce executable code into your environment. Review their source and dependency requirements before installation, and avoid updating every extension while diagnosing one error. Change one component at a time and keep a record of the working versions. Follow the model's license and access conditions when obtaining weights.

This preparation is especially helpful when a graph includes multiple encoders, LoRAs, upscalers, or preprocessing stages. Each component needs to agree with the rest of the pipeline.

## 4. Validate one small sample

Start with one input, one output, and conservative settings appropriate for the model. Keep a fixed seed when the workflow supports it, so later changes are easier to compare. The aim is to validate the complete path from input to saved output.

Check that the intended checkpoint loads, the graph finishes, and the output has the requested dimensions and format. During the run, the Monitor view on your instance page shows GPU memory and utilization over time, alongside the logs. Then repeat the same sample: initial model loading and later generation are different parts of the session, so record them separately.

If memory runs out, reduce batch size or resolution where the workflow permits, inspect which components remain loaded, and reconsider precision or hardware. A smaller file can reduce weight memory while leaving other memory demands substantial. Do not change several settings at once and lose track of what resolved the failure.

Only expand the batch after this sample works. Record total elapsed time and successful outputs for the workload you actually plan to run, rather than treating the first preview as a performance benchmark.

## 5. Save a recovery package before you leave

Export the workflow and save the input assets and selected outputs somewhere you control. Add a small manifest containing the image name, model filenames, custom-node versions, generation settings, and locations of the files needed to rebuild the session.

Datadrive keeps model files, inputs, and outputs between sessions, so you don't download large weights again, and you can upload weights to it without starting an instance. A Snapshot taken after installing custom nodes lets you relaunch the same environment next time. Instance disks are cleared on release, so save to these first. An exported workflow normally describes a graph; it does not bundle every weight file and dependency required to run it.

A useful recovery check is to reopen the exported workflow and repeat the small sample using the saved manifest. This reveals a missing input or undocumented dependency while the original environment is still available. Keep secrets outside that package.

## Account for the whole session

Glows.ai bills GPU compute per second. For planning, the October 2026 RTX 4090 reference rate is $0.49 per GPU-hour. A hypothetical 20 billable minutes on one GPU therefore costs about $0.16 in compute. This is an instance example, not an endpoint price or a measured generation cost.

Include initialization, model downloads, troubleshooting, and idle time in the session estimate. Per-second billing means you pay only while the instance runs, and billing stops when you release it, not when the graph finishes.

## Can the same plan cover vLLM and ComfyUI?

Glows.ai also lists vLLM images, but evaluate those workloads separately. ComfyUI validation concerns graphs, media outputs, and model components; an LLM server needs checks for context length, concurrency, and response latency. A shared cloud account does not make their memory requirements interchangeable.

For your next ComfyUI session, make the first deliverable a small verified workflow and its recovery package. That gives the creative work a dependable starting point as you increase resolution, add nodes, or share the recipe.
