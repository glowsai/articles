# 設定済み ComfyUI イメージを備えた GPU クラウド：Glows.ai ワークフローガイド

設定済み ComfyUI イメージを備えた GPU クラウドは、画像生成を始めるための実用的な出発点になります。用意された ComfyUI 環境から始められるため、実行したいモデルとワークフローに集中できます。Glows.ai は ComfyUI FLUX.1-Kontext、ComfyUI Qwen Image、ComfyUI Wan2.2 14B I2V、ComfyUI LTX-2.3 など多くの ComfyUI イメージに加え、ComfyUI Base などのフレームワークイメージを提供しています。

次に行うべきことは、そのイメージを再現可能な作業環境にすることです。環境を確認し、モデルファイルとノードを揃え、安全なアクセスを確保し、小さなサンプルを実行して、復元に必要なデータを保存します。この手順により、起動に成功しただけの状態と、安心して再開できるワークフローを区別できます。

## 完了させたいワークフローから考える

ハードウェアを選ぶ前に、既存画像の編集、静止画像の生成、より複雑なグラフの作成など、取り組むタスクを一つ決めます。モデルファミリー、予定する解像度、バッチサイズ、必要なカスタムノード、想定する出力形式を記録してください。あるモデルファミリー向けのワークフローでは、別のファミリーとは異なるエンコーダー、ローダー、アダプターが必要になる場合があります。

FLUX.1-Kontext プロジェクトには、ComfyUI FLUX.1-Kontext イメージを選べます。Ubuntu 24.04、CUDA 12.8、Python 3.11、PyTorch 2.7.1、ComfyUI、FLUX.1-Kontext、VNC が含まれています。起動前に、選んだ GPU とワークフローがイメージの要件を満たしていることを確認してください。

自分で環境を組み立てたい場合は、フレームワークイメージも役立ちます。起動前に選択したイメージの説明を読んでください。見慣れた ComfyUI という名前だけでは、どのモデルの重みやカスタムノードが含まれているかはわかりません。

## 1. イメージ、モデル、GPU の組み合わせを確認する

短いチェックリストを使い、デプロイの判断を具体化します。

| 項目 | 初回実行前に確認すること |
| --- | --- |
| イメージ | 正確なイメージ名と記載されたソフトウェアのバージョン |
| ワークフロー | モデルファミリー、必要なノード、想定する入力 |
| 重み | 必要なチェックポイント、エンコーダー、VAE、アダプターの詳細 |
| GPU | 利用可能な VRAM と、選択したソフトウェア構成への対応 |
| ファイル | ダウンロード容量、作業領域、出力の保存先 |

GPU メモリの要件は、精度、解像度、バッチサイズ、グラフ自体によって変わります。Glows.ai の RTX 4090 は 24GB の VRAM を搭載していますが、この仕様はすべての FLUX や動画ワークフローが収まることを保証するものではありません。中間テンソルや読み込まれる他のコンポーネントのために余裕を確保し、実際のグラフをテストしてください。 グラフにより多くのメモリが必要な場合、Glows.ai では 48GB GPU（RTX 6000 Ada、L40S）と 80GB GPU（A100、H100）も選べます。

初回から大きなバッチを実行するのは避けましょう。小さくても代表的なワークフローを使えば、課金時間をさらに費やす前に、不足ファイルやメモリの負荷を把握しやすくなります。

## 2. アクセスを適切に制御する

Glows.ai は、インスタンスを操作するための SSH に対応しています。選択したデプロイで提供されるアクセス情報を使い、ファイルの確認、ログの閲覧、環境の管理を行ってください。VNC が利用できるかどうかはイメージによって異なります。

ComfyUI の画面を非公開で開く最も簡単な方法は、SSH トンネルです。ComfyUI はポート 8188 で動作し、ログイン機能を標準では備えていません。インスタンスの Access タブにある SSH Command に `-L 8188:localhost:8188` を追加して接続を維持し、ブラウザーで `http://localhost:8188` を開いてください。

認証情報やアクセス URL を、共有するワークフローファイルや公開スクリーンショットに含めないでください。チームメンバーも画面を使う場合は、非公開の素材をアップロードする前に認証を設定し、Glows.ai の IP ACL で会社や VPN の IP アドレスからの接続だけを許可します。作業に必要なポートだけを開放してください。

インターフェースが応答しない場合は、まずサービスが稼働しているかを確認し、ログを調べます。インスタンスを繰り返し起動し直すと、元のエラーが見えにくくなり、依存関係の不足を解決できないままセットアップ時間が増えることがあります。

## 3. モデルとカスタムノードを段階的に揃える

選択したモデルに対応するワークフローを読み込みます。モデル不足とノード不足のメッセージは、分けて確認してください。ノードのパッケージをインストールしても、そのチェックポイントが揃うわけではありません。また、チェックポイントをダウンロードしても、それを読み込むコードはインストールされません。

必要な重みファイルごとに、入手元、ファイル名、モデルファミリー、精度、選択したイメージ内の保存先を記録します。ワークフローの説明と、イメージの実際のディレクトリ構成に従ってください。別のデプロイからコピーしたパスは、元の環境では正しくても、現在の環境では使えない場合があります。

カスタムノードを導入すると、実行可能なコードが環境に追加されます。インストール前にソースと依存関係の要件を確認し、一つのエラーを調査しているときにすべての拡張機能を更新することは避けてください。一度に変更するコンポーネントは一つにし、正常に動作するバージョンを記録します。重みを入手するときは、モデルのライセンスとアクセス条件に従ってください。

グラフに複数のエンコーダー、LoRA、アップスケーラー、前処理の段階が含まれる場合、この準備は特に役立ちます。各コンポーネントは、パイプラインの他の部分と整合している必要があります。

## 4. 小さなサンプルを一つ検証する

入力一つ、出力一つから始め、モデルに適した控えめな設定を使います。ワークフローが対応している場合はシード値を固定すると、後の変更を比較しやすくなります。目的は、入力から出力の保存までの経路全体を検証することです。

意図したチェックポイントが読み込まれ、グラフが最後まで実行され、出力が指定したサイズと形式になっていることを確認します。実行中はインスタンスページの Monitor で GPU メモリと使用率の推移を確認し、ログも確認してください。その後、同じサンプルをもう一度実行します。初回のモデル読み込みと、その後の生成は作業の異なる段階なので、分けて記録してください。

メモリが不足した場合は、ワークフローが許す範囲でバッチサイズや解像度を下げ、どのコンポーネントが読み込まれたままかを確認し、精度やハードウェアを見直します。ファイルが小さくなれば重みのメモリ使用量は減らせますが、他のメモリ需要は依然として大きい場合があります。複数の設定を一度に変更して、何が問題を解決したのかわからなくなることを避けてください。

このサンプルが動作してから、バッチを拡大します。最初のプレビューを性能ベンチマークとして扱うのではなく、実際に実行する予定のワークロードについて、総経過時間と成功した出力数を記録してください。

## 5. 作業を終える前に復元用データを保存する

ワークフローをエクスポートし、入力素材と選んだ出力を、自分で管理できる場所に保存します。イメージ名、モデルのファイル名、カスタムノードのバージョン、生成設定、作業環境の再構築に必要なファイルの場所をまとめた簡単な一覧も添えてください。

Datadrive は利用の合間もモデルファイル、入力素材、出力を保持するため、大きな重みを再ダウンロードせずに済みます。インスタンスを起動せずに重みをアップロードすることもできます。カスタムノードをインストールした後に Snapshot を保存すれば、次回も同じ環境で起動できます。インスタンスのディスクは解放時に消去されるため、先に保存してください。エクスポートしたワークフローは通常、グラフを記述するものであり、実行に必要なすべての重みファイルや依存関係をまとめて含むわけではありません。

有用な復元確認の方法は、エクスポートしたワークフローを開き直し、保存した一覧に従って小さなサンプルを再実行することです。元の環境がまだ使えるうちに、不足している入力や未記録の依存関係を発見できます。機密情報は復元用データに含めないでください。

## 作業全体の時間を費用に含める

Glows.ai の GPU 計算リソースは秒単位で課金されます。計画時の参考として、2026 年 10 月の RTX 4090 の単価は GPU 1 基・1 時間あたり $0.49 です。仮に GPU 1 基を課金対象時間で 20 分間使用すると、計算費用は約 $0.16 になります。これはインスタンスの費用例であり、エンドポイントの料金や実測した生成コストではありません。

作業時間の見積もりには、初期化、モデルのダウンロード、トラブルシューティング、アイドル時間を含めます。秒単位課金ではインスタンスが稼働している時間だけ支払い、解放すると課金が停止します。グラフの実行が完了しただけでは課金は停止しません。

## 同じ計画を vLLM と ComfyUI の両方に使えるか？

Glows.ai には vLLM イメージも掲載されていますが、これらのワークロードは別々に評価してください。ComfyUI の検証対象はグラフ、メディア出力、モデルのコンポーネントです。一方、LLM サーバーではコンテキスト長、同時実行数、応答レイテンシの確認が必要です。同じクラウドアカウントを使うからといって、両者のメモリ要件をそのまま流用できるわけではありません。

次に ComfyUI を使うときは、まず検証済みの小さなワークフローと、その復元用データを用意しましょう。解像度を上げたり、ノードを追加したり、手順を共有したりする際に、制作作業の確かな出発点になります。
