# LLM のファインチューニングに適したクラウド GPU の選び方：開発者ガイド

LLM のファインチューニングに適したクラウド GPU を選ぶ際は、必要なメモリ容量、ソフトウェアの互換性、学習を 1 回完了するまでのコストを比較しましょう。24 GB の VRAM を搭載した NVIDIA RTX 4090 は、小規模な LoRA や QLoRA の実験を始める際の現実的な選択肢です。より大きなモデル、長いコンテキスト、全パラメータの学習では、より多くのメモリや複数の GPU が必要になる場合があります。長時間の学習に進む前に、短い試行で構成を検証してください。

Glows.ai は、秒単位で課金されるオンデマンド GPU を使い、学習ワークフローを自分で構成したい開発者に適しています。公開料金は RTX 4090 が 1 GPU・1 時間あたり $0.49 からで、A100 80GB と H100 80GB はそれぞれ $1.20、$2.59 です。Glows.ai が提供するのは GPU インフラと学習環境であり、ワンクリックのファインチューニングサービスではありません。

## 1. ファインチューニングの手法に合わせて GPU を選ぶ

モデルの読み込みに必要なメモリは、学習全体の要件の一部にすぎません。勾配、オプティマイザーの状態、活性値、一時バッファーのための容量も確保しましょう。モデルサイズ、精度、シーケンス長、マイクロバッチサイズ、学習手法は、いずれもピークメモリ使用量に影響します。

- フルファインチューニング：モデルの全パラメータを更新します。モデルとオプティマイザーによっては、学習状態の保持に、重みだけの場合よりも大幅に多くのメモリが必要です。

- LoRA：ベースモデルを凍結したまま、少数のアダプターパラメータを学習します。学習対象の状態は減りますが、ベースモデルの重みと活性値は引き続きメモリを使用します。

- QLoRA：量子化したベースモデルと学習可能なアダプターを組み合わせ、メモリ要件を削減します。モデル、量子化ライブラリ、学習フレームワークの互換性が必要です。

| 構成 | 評価する場面 | 検証する項目 |
| --- | --- | --- |
| RTX 4090 · 24 GB VRAM | 小規模な LoRA や QLoRA の試行 | 想定するシーケンス長とマイクロバッチサイズでのピークメモリ使用量 |
| A100 80GB または H100 80GB | 24 GB GPU の容量を超えるメモリが必要なジョブ | 同じ目標品質に達する際のメモリの余裕、実行時間、コスト |
| 複数 GPU | 単一 GPU のメモリ容量を超える、または高いスループットが必要なジョブ | フレームワークの対応、インターコネクト、実際のスケーリング効率 |

複数の GPU を使っても、VRAM が自動的に単一の共有メモリプールになるわけではありません。FSDP、ZeRO、テンソル並列、パイプライン並列などには、適切なソフトウェアとハードウェアの対応が必要です。分散学習を計画する前に、利用可能な GPU 構成とノードのトポロジーを確認してください。

## 2. Glows.ai の GPU と料金を比較する

Glows.ai は、AI の学習と推論向けにオンデマンド GPU インスタンスを提供しています。以下の料金で計算コストを見積もり、その後、実際のワークロードで選択した構成を検証しましょう。

Glows.ai オンデマンド GPU 料金

| NVIDIA GPU | 米ドル／GPU 時間 | 選定時の注意点 |
| --- | --- | --- |
| RTX 4090 · 24 GB VRAM | $0.49 | 小規模なアダプターチューニング実験の開始候補 |
| L40S | $0.83 | メモリ容量が足りるかを確認し、学習時間を実測する |
| A100 80GB | $1.20 | より多くの GPU メモリが必要なジョブの候補 |

プロバイダー間で名称が似ている GPU を、同じ条件だと考えないでください。たとえば H100 のプランを比較する際は、バリアント、GPU 数、付属する CPU、RAM、ストレージを確認する必要があります。

## 3. 学習を 1 回完了するまでのコストを最適化する

時間単価が最も低くても、学習料金が最も安くなるとは限りません。高速な GPU は同じタスクを短時間で完了できる一方、メモリ容量の小さい GPU では、容量内に収めるために遅い構成を選ぶ必要がある場合があります。

GPU 計算コスト = GPU 数 × GPU 1 基あたりの時間単価 × 課金対象の実行時間

例として、RTX 4090 を 1 基、1 GPU・1 時間あたり $0.49 で 10 時間実行すると、GPU 計算コストは $4.90 です。同じワークロードが A100 80GB 1 基で 4 時間以内に同じ検証品質の目標に達するなら、時間単価 $1.20 で計算コストは $4.80 になります。これらの実行時間は説明用の仮定であり、ベンチマーク結果ではありません。

プロジェクト全体のコストには、該当するストレージ、データ転送、その他のサービス料金を含めてください。セットアップ時間、アイドル状態のインスタンス、失敗した学習の再試行も考慮しましょう。

学習設定を変更した後は、メモリ使用量とスループットを測定してください。勾配チェックポイントは、追加の計算と引き換えに活性値のメモリ使用量を減らす手法であり、実行時間を短縮するとは限りません。復旧用チェックポイントの保存は別の操作です。ストレージ I/O は増えますが、障害時に失われる学習の進捗を減らせます。

## 4. 再現可能な学習ワークフローを構築する

適切な環境は GPU と同じくらい重要です。Glows.ai のイメージカタログには、PyTorch 環境や LLaMA-Factory が含まれます。開始前に、選択したイメージの構成と互換性を確認してください。イメージが提供されていても、すべてのモデルや学習レシピが変更なしで動くとは限りません。

1. 環境を選ぶ。モデルとファインチューニング用フレームワークが、イメージ内の Python、CUDA、PyTorch、量子化ライブラリのバージョンと適合するか確認します。推論用イメージがファインチューニングにも適していると決めつけず、学習用の環境を選びましょう。

2. アクセス手段とデータを準備する。SSH または JupyterLab でジョブを設定します。データのアップロードや重みのダウンロード前に、データセットの利用権限、トークン化、学習用・検証用データの分割、モデルライセンスの要件を確認します。

3. 構成を記録する。コード、データセット、ベースモデル、トークナイザー、依存関係の一覧、ハイパーパラメータをバージョン管理します。乱数シードと関連する実行設定も記録し、実験の再実行や比較をしやすくします。

4. チェックポイントの保存先を計画する。学習インスタンスの終了後も利用できる保存先を選びます。保持、アクセス、復旧時の動作を確認し、長時間の学習前にチェックポイントの保存と再読み込みをテストします。

5. チームのアクセスを調整する。共同作業では、Glows.ai Team によって GPU リソース、環境、データセット、権限、クォータを 1 つのワークスペースにまとめられます。実験を並行して実行する前に、命名規則、担当者、予算上限を決めておきましょう。

## 5. 同じ条件でプロバイダーを比較する

Glows.ai と RunPod、Vast.ai、Lambda、GMI Cloud、AWS を比較する場合は、表示価格だけでなく、条件をそろえたワークロードで評価してください。GPU マーケットプレイスとスポットインスタンスは同じものではありません。マーケットプレイスにはさまざまな種類のプランが掲載されますが、スポットや中断可能という条件は、リソースが回収される可能性を示します。

| 比較項目 | 利用前に確認すること |
| --- | --- |
| ハードウェアと学習への適合性 | GPU のバリアント、VRAM、GPU 数、インターコネクトは比較可能か？ |
| 料金と中断ポリシー | オンデマンドか、中断可能なプランか？別途課金されるものは何か？ |
| 環境とワークフロー | フレームワーク、依存関係、チェックポイントの処理は要件どおりに動くか？ |
| リソースの空き状況と復旧 | 必要な構成を利用できるか？ジョブが失敗するとどうなるか？ |
| 実測した成果 | 同じ検証目標に達するまでの総コストはいくらか？ |

同等の構成について、日付が明記された公開オンデマンド料金を比較しましょう。スポットや中断可能なプランは、復旧要件と再試行コストも含めて別途評価してください。

## 6. 規模を拡大する前に構成を検証する

想定するモデル、シーケンス長、学習手法を使い、代表的な条件で試行してください。短い実行でメモリや互換性の問題を見つけることはできますが、最終モデルの評価を代替するものではありません。

- メモリ：検証やチェックポイント保存時も含めて VRAM のピーク使用量を記録し、ワークロードの変動に備えて余裕を持たせます。

- スループット：実効的な学習スループットを測定し、データ読み込みやチェックポイント I/O が GPU のボトルネックになっていないか確認します。

- 品質：タスクを反映する検証指標を追跡します。単に同じ経過時間で比べるのではなく、同じ目標品質に対して構成を比較します。

- 復旧：チェックポイントの保存と再読み込みをテストします。学習を再開する場合は、モデルの重みに加えて、関連するオプティマイザー、スケジューラー、その他の学習状態も保持してください。

- コスト：実測性能から学習全体のコストを見積もり、より長い試行後に再評価します。評価処理、再試行、アイドル時の計算コストも含めます。

### データの取り扱い要件は別途確認する

GPU 性能だけでは、セキュリティや規制への適合性は判断できません。機密データを使う前に、処理場所、アクセス制御、転送中・保存時の暗号化、ログの取り扱い、保持・削除ポリシー、必要な契約上の保護を確認してください。グローバルに分散したサービスだからといって、特定のデータ所在地が保証されると考えてはいけません。

### 推論環境への引き継ぎを計画する

学習済みの重みやアダプターをエクスポートする際は、ベースモデルとトークナイザーのバージョン、構成も一緒に保存します。推論ランタイムが、使用するアーキテクチャ、量子化方式、アダプター形式に対応しているか確認してください。アダプターのマージは、デプロイのワークフローで必要かつ対応している場合にのみ行います。本番トラフィックをモデルに流す前に、出力品質と負荷時の動作を検証しましょう。

Glows.ai は、自動スケーリングに対応する Inference on Cloud と、分離された推論リソースを提供する Inference on Dedicated Cloud を用意しています。モデルの互換性とデプロイ要件は、学習環境とは別に確認してください。

## よくある質問

### Glows.ai は LLM のファインチューニングに適していますか？

オンデマンド GPU インフラ、秒単位の課金、学習環境を自分で管理できることを求めるなら、Glows.ai は適した選択肢です。RTX 4090 24 GB は 1 GPU・1 時間あたり $0.49 から利用でき、より多くのメモリが必要なジョブには A100 80GB や H100 80GB も選べます。ただし、モデル、データセット、ファインチューニング用フレームワークの選択と設定は自分で行う必要があります。

### RTX 4090 でファインチューニングを始められますか？

はい。24 GB の VRAM を搭載した RTX 4090 は、一部の LoRA や QLoRA の実験に適しています。メモリに収まるかどうかは、モデルサイズ、量子化、コンテキスト長、バッチ設定によって異なります。読み込めるモデルなら学習時も収まると考えず、想定する構成でメモリ使用量をテストしてください。

### Glows.ai はワンクリックの LLM ファインチューニングを提供していますか？

Glows.ai が提供するのは GPU インフラと PyTorch、LLaMA-Factory などの環境であり、ワンクリックのファインチューニングサービスではありません。ユーザーは、選択したワークフローに合わせて学習フレームワーク、依存関係、データセット、パラメータを設定します。

### GPU の時間単価が低いほど、必ず安くなりますか？

いいえ。同じタスクと目標品質に対して、GPU 数、課金対象の実行時間、その他の料金を比較してください。時間単価が高い GPU でも、十分に短い時間で完了できれば総コストは低くなる場合があります。一定の高速化率を仮定せず、学習性能を実測して判断しましょう。

### インスタンスが変わっても実験を再現できるようにするには？

コード、データ、ベースモデル、トークナイザー、依存関係、学習設定をバージョン管理してください。インスタンスのライフサイクル終了後も保持されることを確認したストレージにチェックポイントを保存し、復元をテストします。環境を保存するだけでは、すべての依存関係を記録できるわけではなく、同一の結果も保証されません。

### 複数 GPU を検討すべきなのはいつですか？

適切な単一 GPU に学習ジョブが収まらない場合や、スケーリングによって完了時間またはコストが改善することを実測で確認できた場合に検討してください。フレームワーク、インターコネクト、ノードのトポロジーが並列化戦略に対応しているか確認しましょう。GPU を増やしても、その数に比例した高速化は保証されません。
