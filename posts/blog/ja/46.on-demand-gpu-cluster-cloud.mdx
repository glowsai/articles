# 最適なオンデマンド GPU クラスタークラウド：Glows.ai での選び方と拡張方法

最適なオンデマンド GPU クラスタークラウドは、時間、品質、予算の要件を満たして分散ワークロードを完了できるものです。Glows.ai は On-Demand Cloud、Virtualized On-Demand Clusters、Bare Metal Clusters を提供しており、プロジェクトが GPU 1 基の規模を超えた際に、チームは複数のインフラ導入方法を選べます。

まず、GPU 同士の協調動作が必要なのか、単に独立したワーカーを増やしたいのかを判断してください。この違いによって、ネットワーク、オーケストレーション、課金について確認すべき内容が決まります。このガイドでは、構成の選択、有用な試行の設計、実際に完了させるべき仕事に基づく Glows.ai の評価方法を説明します。

## GPU クラスターとは何か？

GPU クラスターは、複数のマシンにまたがるリソースを協調させます。GPU 間で継続的に通信するジョブもあれば、ほぼ独立したタスクを分散するジョブもあります。マルチ GPU サーバーは複数のアクセラレーターを搭載した 1 台のマシンであり、マルチノードクラスターではサーバー間の通信も加わります。

複数のインスタンスを借りるだけで、協調する学習システムができるわけではありません。フレームワーク、ネットワーク、ストレージ、起動手順が、意図する実行パターンに対応している必要があります。

| ワークロード | GPU の追加で実現すること | 最初に確認すること |
| --- | --- | --- |
| 独立した実験 | より多くの試行を同時に実行する | 各ワーカーは頻繁な通信なしで動作できるか？ |
| データ並列学習 | バッチを分割し、更新を交換する | 通信があっても有用なスケーリングを維持できるか？ |
| モデル並列学習 | モデルの計算と状態を分散する | メモリとトポロジーの計画全体が機能するか？ |
| 分散推論 | モデルまたは推論サービスのワークロードを分散する | 目的はメモリ容量、スループット、それとも両方か？ |

独立した実験であれば、ワーカーのプールだけで十分な場合があります。密に結合した学習では、ワーカー間の接続が、追加 GPU の費用に見合う効果を得られるかどうかを左右します。

## Glows.ai の位置づけ

Glows.ai は、クラスター製品の選択肢に加え、RTX 4090 から B300 までの NVIDIA GPU を開発者に提供しています。実用上の利点は、小規模な実験、協調するワークロード、チームの共有リソースを、一つのプラットフォームで評価できることです。

On-Demand Cloud でベースラインを確立してください。協調する構成が必要なら Virtualized On-Demand Clusters を相談し、ワークロードや運用要件がベアメタルの導入形態を求めるなら Bare Metal Clusters を相談します。選択する前に、構成ごとの詳細を確認してください。

Glows.ai Team は、共有 GPU リソース、環境、データセット、権限、クォータを提供します。チームメンバーは共有 Snapshot から起動し、チームの Datadrive から同じデータを読み込めるため、試行に参加するすべてのエンジニアが同じ環境から始められます。

## クラスターを選ぶ前にワークロードを決める

モデルまたはアプリケーション、フレームワークのバージョン、学習方法、精度、入力サイズ、バッチ設定、データセットの場所、完了目標を簡潔にまとめてください。一つの結果を早く得たいのか、多数の独立した結果を並列に得たいのかを明記します。

学習では、検証の合格基準を含めてください。ステップが高速でも、最終的なモデルがタスク要件を満たさなければ意味がありません。推論では、リクエスト長、同時実行数、出力品質、レイテンシ目標を含めます。

メモリ計画は、実際の実行方式を対象にする必要があります。重みは学習メモリの一部にすぎず、勾配、オプティマイザーの状態、活性化、作業用バッファーもメモリを使います。推論サービスでは、実行時バッファーや KV キャッシュが大きくなることがあります。公称 VRAM 容量を足しても、自動的に使える単一のメモリプールができるわけではありません。

## GPU 周辺の構成を比較する

GPU の数とバリアント、ノードあたりの GPU 数、CPU と RAM、ローカルおよび共有ストレージ、ノード内とノード間の接続を含む構成を書面で求めてください。

次に、ジョブの起動方法を確認します。提案された構成は、使用するフレームワークの分散バックエンドに対応していますか？ オーケストレーターは誰がインストール、管理しますか？ アプリケーションには、どのネットワーク経路と権限が必要ですか？

「クラスター」という言葉だけから、InfiniBand、NVLink、RDMA、マネージドスケジューラー、特定の帯域幅を推測しないでください。Glows.ai では、H100 8 基を搭載したノード全体を利用する場合に NVLink に対応し、RTX 4090、L40S、RTX PRO 6000 の複数 GPU は PCIe で接続されます。マルチ GPU 通信には NCCL が対応し、Mesh Clustering により同じリージョンのインスタンスをプライベートネットワークで接続できます。マルチノードクラスターについては、具体的な提案のトポロジーと運用責任をお問い合わせください。

## 同じタスクでスケーリングを測定する

実行可能な最小構成で、代表的なベースラインを測定します。次に、提案された大きなリソース割り当てで同じワークロードを繰り返し、入力、学習目標、合格条件を維持してください。

1 秒あたりの完了作業量、総経過時間、GPU 数、メモリ使用量、データ読み込み時間、通信オーバーヘッド、チェックポイントにかかる時間を記録します。遅いワーカーを調べてください。同期するジョブは、一つのボトルネックを待つために時間を費やす場合があります。 各インスタンスページの Monitor では GPU 使用率とメモリの推移を確認でき、全体を遅らせているワーカーを見つけるのに役立ちます。

完了する作業量が同じ場合：

高速化率 = ベースラインの実行時間 ÷ 大きな構成の実行時間。

ベースラインが GPU 1 基なら、スケーリング効率 = 高速化率 ÷ 大きな構成の GPU 数です。複数 GPU のベースラインでは、代わりに GPU 数の比率を分母に使います。これらの計算は実測したスケーリングを表すものであり、プラットフォームが約束する結果ではありません。

## 時間単価を解釈する前に GPU 時間を計算する

以下は仮定の例です。同じタスクを完了し、GPU あたりの単価が同じで、別途のサービス料金を含まないと仮定しています。

| 割り当ての例 | 完了時間 | GPU 時間 |
| --- | --- | --- |
| GPU 1 基 | 8 時間 | 8 |
| GPU 4 基 | 3 時間 | 12 |
| GPU 4 基、別の実測結果 | 1.5 時間 | 6 |

3 時間の結果は早く完了しますが、GPU 時間は 50% 増えます。1.5 時間の結果では 25% 減ります。4 基借りるだけで、どちらかの結果が自動的に得られるわけではありません。

請求額には、実際の見積もりと課金規則を適用してください。ノード単位の見積もりならノード料金を使い、GPU 単位の料金であるかのように再度掛け算しないでください。Glows.ai のオンデマンドインスタンスは最低レンタル時間なしの秒単位課金で、データ転送にも通常は追加料金がかかりません。Virtualized On-Demand Clusters と Bare Metal Clusters は構成別の見積もりとなるため、最小割り当て、利用コミットメント、セットアップ時間は見積もりで確認してください。

## 障害復旧と引き継ぎを試行に含める

チェックポイントや中間結果を保存し、予定するストレージ構成でジョブを再開できるかをテストします。学習の再開には、重みに加えてオプティマイザーとスケジューラーの状態が必要になる場合があります。 Glows.ai では同じリージョンの各インスタンスに同じ Datadrive をマウントできます。すべてのワーカーが一つのデータセットを読み込み、同じ保存先にチェックポイントを書き込めるうえ、インスタンス解放後もデータが保持されます。

イメージの識別情報、コードのコミット、モデルとデータセットの版、起動コマンド、ワーカー数、成果物の場所を実行記録に残してください。権限を持つ別のメンバーに、起動手順を再現してもらいます。共有アクセスは有用ですが、明確な手順があって初めて実際に活用できます。

実行後の割り当ての解放方法を事前に合意してください。オンデマンドインスタンスは解放すると課金が停止します。Glows.ai の SDK API を使えば、ジョブ終了時にワークフローから自動的に解放し、アイドル状態のノードに課金が続くことを防げます。

## クラスターを選ぶ前によくある質問

### クラスターは常に GPU 1 基より優れていますか？

いいえ。大きなリソース割り当ては完了時間や実験の処理量を改善する場合がありますが、協調動作やデータ移動の負担が増えます。タスク全体に利点がある場合にクラスターを使ってください。

### Glows.ai はオンデマンドとベアメタルのクラスターを提供していますか？

はい。Virtualized On-Demand Clusters は長期クラスターを予約せずに拡張・縮小でき、Bare Metal Clusters は長期学習向けに専用ハードウェアと完全な制御権を提供します。ワークロードを添えて [hi@glows.ai](mailto:hi@glows.ai) までお問い合わせいただくと、適切な規模、トポロジー、条件をご案内できます。

### 公開された H100 インスタンス料金でクラスターの価格を計算できますか？

単一の 8 GPU ノードであれば可能です。オンデマンドの H100 8 基のインスタンスは 1 時間あたり $20.72 と公開されており、H100 1 基の料金のちょうど 8 倍です。マルチノードクラスターでは、ノード構成、ネットワーク、購入条件が価格に影響するため、構成別の見積もりを使ってください。

### 最初の Glows.ai の試行で何を確認すべきですか？

メモリ要件への適合、有用なスケーリング、復旧、チームへの引き継ぎ、合格した結果を得るまでの総費用です。これらの知見が、容量を拡張するための確かな根拠になります。

実行要件をまとめて、[Glows.ai](https://glows.ai/ja/) とその[ドキュメント](https://docs.glows.ai/ja/)を確認してください。測定可能なベースラインから始め、ワークフローに実際の価値をもたらすクラスター構成を選びましょう。
